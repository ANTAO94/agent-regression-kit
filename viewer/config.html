02比较策略

这一节控制“baseline 发生了什么变化时要阻断”。允许差异仍会显示在报告中，只是不让命令失败。

claims-only 仍然严格检查 claims、工具、参数、结果和错误状态。

理解方式：allow_* 是“哪些变化不阻断”；下面的 contract 是“candidate 必须怎样运行”。不要用 allow-path 掩盖一个应该写成契约的危险行为。

03行为契约

Contract 是 Agent 的可执行规则：它不猜模型想法，只检查你明确记录下来的工具、claims、路径和状态。

C
把产品要求写成可以失败的规则

例如“查询订单必须调用 get_order，不能调用 delete_order，最终状态必须是 not_shipped，最多调用 5 步”。

留空表示不设置上限；用于防止循环调用和异常成本。

路径规则每行一条，使用 -> 连接工具名。

必须调用的工具

must_call

禁止调用的工具

must_not_call

字段断言

equals · contains · exists

路径示例：final_answer.claims.order_status。equals 和 contains 的值支持 JSON；普通文字会按字符串处理。

允许的完整工具路径

path_rules.any_of

每行是一条完整合法路径。字符串工具规则只检查工具名，不限制参数；如果参数是产品契约，请用必须调用或 baseline 比较固定下来。

业务副作用

side_effects

需要工具执行器提供 world state 快照，例如 orders.123.status 从 paid 变成 cancelled。

04噪音过滤与脱敏

只处理已知、可解释的动态字段。过滤越宽，测试越容易通过，但证据越弱。

支持 [*]。适合 request ID、trace ID 等不承载业务语义的字段。

每行一条。页面不会把它保存到浏览器草稿；下载的 JSON 仍会包含输入值，请确认后再提交。

确定性归一化

normalizers

timestamp 把值归一化为时间戳占位符；sort 对列表按稳定表示排序。当前版本不支持任意正则重写。

安全提示：脱敏不是数据防泄露系统。请在 CI 报告上传前检查 Trace、工具返回值和最终文本，尤其是自由文本中的密钥。

05检查并导出

导出前先看右侧 JSON。配置页面不会自动写入仓库，确认无误后下载，再把文件放进项目的 .agent-regression/ 目录。

推荐流程：下载 JSON → 放入项目 → 执行 agent-regression config validate → 再运行 compare。页面状态通过不代表真实文件路径和 Trace 内容一定存在。
