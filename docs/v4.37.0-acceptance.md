# v4.37.0 Acceptance Record / 验收记录

Date / 日期: 2026-09-21

## Release intent / 发布目标

v4.37 adds reviewed per-case Contracts to batch comparison. A business matrix
can now compare many relative Trace files with one CI gate while each case
declares its own expected claims, required tools and business relations.

v4.37 为批量比较增加按用例配置经过审核的 Contract。业务用例矩阵可以共用一个 CI 门禁，
同时让每个相对 Trace 文件声明自己的业务断言、必需工具和跨步骤关系。

This is additive. Existing batch configs and the public
`compare_trace_batch(baseline_dir, candidate_dir, policy=None)` call remain
valid; `case_policies` is optional.

这是兼容性增量能力。已有批量配置和公开的
`compare_trace_batch(baseline_dir, candidate_dir, policy=None)` 调用继续有效，
`case_policies` 为可选参数。

## Accepted behavior / 已验收行为

- `case_contracts` is accepted only as a mapping from safe relative
  `*.trace.json` paths to normal Contract objects.
- A configured case Contract replaces the default batch Contract only for that
  relative path.
- The selected policy is present in each case comparison report.
- Unsafe paths, non-Trace paths, malformed Contracts and missing Trace files
  fail closed.
- A two-case matrix with different reviewed expected statuses passes while
  retaining different Contracts for the two cases.

- `case_contracts` 只接受安全的相对 `*.trace.json` 路径到普通 Contract 的映射。
- 配置的 case Contract 只覆盖对应路径，不影响默认批量 Contract。
- 每个 case 的比较报告会保留实际采用的策略。
- 不安全路径、非 Trace 路径、错误 Contract 和缺失 Trace 都会 fail-closed。
- 两个拥有不同审核状态和不同 Contract 的用例可以同时通过批量门禁。

## Configuration boundary / 配置边界

`case_contracts` is for independently reviewed expected behavior. It does not
make a candidate pass by itself: normal Trace validation, event comparison,
Contract checks and missing-file checks still run. The map also does not
support arbitrary filesystem paths or silently ignore typoed fields.

`case_contracts` 用于声明经过独立审核的预期行为。它本身不会让候选结果自动通过：Trace 校验、
事件比较、Contract 检查和缺失文件检查仍然执行；路径不能任意指向文件系统，也不会静默忽略拼写错误。

## Evidence boundary / 证据边界

This release proves that the framework can express and audit a heterogeneous
deterministic business matrix. It does not prove that the Contracts are
complete for every business, that an Agent is correct on unseen tasks, or that
external teams have adopted the feature.

这些结果证明框架可以表达并审计包含不同业务结果的确定性用例矩阵，但不代表 Contract 已覆盖
所有业务、不代表 Agent 在未见任务上正确，也不代表外部团队已经采用该能力。
