# v4.38.0 Acceptance Record / 验收记录

## Release intent / 发布目标

v4.38 adds a reproducible external-business validation against the pinned
public [poysa213/HelpPilot](https://github.com/poysa213/HelpPilot) project. The
candidate project keeps ownership of its LangGraph graph, SQLite tools, RAG
boundary and human-approval interrupt. Agent Regression Kit supplies only the
adapter, reviewed Trace baseline, Contract, comparison command and CI gate.

v4.38 增加一条可复现的独立业务流程验证，接入固定版本的公开
[poysa213/HelpPilot](https://github.com/poysa213/HelpPilot) 项目。候选项目继续负责自己的
LangGraph 图、SQLite 工具、RAG 边界和人工审批 interrupt；Agent Regression Kit 只负责接入脚本、
审核后的 Trace baseline、Contract、比较命令和 CI 门禁。

This is integration evidence, not an adoption claim. The external project is
run with seeded demo data and deterministic model/retrieval substitutions; no
Groq, LangSmith, payment or customer credentials are used.

这是接入证据，不是上游采用声明。候选项目使用 seed/demo 数据和确定性模型/检索替身运行；没有使用
Groq、LangSmith、支付凭证或客户数据。

## Scenario / 验证场景

The recorded business path is a lost-order refund that must pause before the
side effect:

```text
get_order
  → get_tracking
  → check_refund_policy
  → create_refund_draft
  → human approval interrupt
  → issue_refund
  → cited final reply
```

记录的业务路径是一个丢件退款流程，必须在副作用前暂停：

```text
查询订单 → 查询物流 → 检查退款政策 → 创建退款草稿
→ 人工审批 interrupt → 执行退款 → 带引用的最终回复
```

The adapter verifies that `issue_refund` is absent before resume and present
only after `approved=True`. The final Claims are derived from the resumed
HelpPilot state and its SQLite action log, not pre-filled from the expected
answer.

接入脚本会验证恢复前不存在 `issue_refund`，且只有 `approved=True` 恢复后才出现该调用。最终 Claims
来自恢复后的 HelpPilot state 和 SQLite action log，而不是预先把期望答案写入 Trace。

## Reproduce / 复现

From the repository root:

在仓库根目录执行：

```bash
git clone https://github.com/poysa213/HelpPilot.git /tmp/helppilot
git -C /tmp/helppilot checkout 3767824fb90b89a8b19fc4169d912645aaf6fe0b
uv sync --directory /tmp/helppilot

export ARK_ROOT="$PWD"
PYTHONPATH="$ARK_ROOT/src" uv run --directory /tmp/helppilot python \
  "$ARK_ROOT/examples/external-pilot/helppilot/record_trace.py" \
  --project-dir /tmp/helppilot \
  --out "$ARK_ROOT/work/helppilot/candidate.trace.json"

PYTHONPATH="$ARK_ROOT/src" python3 -m agent_regression compare \
  --config "$ARK_ROOT/examples/external-pilot/helppilot/compare.config.json"
```

Run the dedicated workflow manually when the external dependency or its
commit changes. It uploads the candidate Trace and all comparison reports as
an artifact; it does not send a request to an online model.

外部依赖或固定 commit 变化时，手动运行专用 workflow。工作流会上传 candidate Trace 和全部比较报告作为
artifact；它不会请求在线模型。

## Evidence boundary / 证据边界

This release proves that the framework can cross a real external Agent's
graph, tool, retrieval and approval boundaries and catch three business-shaped
regressions. It does not prove HelpPilot production quality, upstream
maintainer adoption, online-model factuality, payment safety, or general
compatibility with all LangGraph projects.

本版本证明框架可以穿过一个独立 Agent 的 graph、工具、检索和人工审批边界，并阻断三类贴近业务的回归。
它不证明 HelpPilot 的生产质量、上游维护者采用、在线模型事实性、支付安全，也不代表兼容所有 LangGraph 项目。

The next evidence needed is a project owner review, real model repeat runs,
historical regression cases, and at least two real change cycles. Until those
exist, this remains a maintainer-run technical/business pilot rather than an
external adoption study.

下一步仍需要项目负责人审核、真实模型重复运行、历史回归案例和至少两个真实改动周期。在这些证据出现前，
本项目仍是维护者执行的技术/业务预演，不是外部采用研究。
