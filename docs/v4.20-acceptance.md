# v4.20 acceptance / v4.20 验收

## Scope / 范围

v4.20 adds a task-disjoint holdout proxy on top of the actor-aware telecom
adapter. The split is selected from task IDs only:

- SHA-256 the UTF-8 task ID;
- take the first eight hexadecimal digits modulo `100`;
- reserve buckets `0..19` for holdout and the rest for calibration;
- verify task-set counts and canonical SHA-256 digests before evaluation.

v4.20 在 actor-aware 电信适配器之上增加了 task-disjoint holdout 代理验证。分桶只使用
任务 ID：对 UTF-8 task ID 做 SHA-256，取前 8 位十六进制数对 100 求模，`0..19` 进入
holdout，其余进入 calibration；执行前校验任务数量和规范化任务集合哈希。

## Reproduce / 复现

```bash
mkdir -p work/tau2-telecom-holdout
PYTHONPATH=src python examples/tau2_telecom_holdout_validation.py \
  --results work/tau2-telecom/results.json \
  --source-manifest examples/tau2-telecom/source.json \
  --split-definition examples/tau2-telecom/task-split.json \
  --partition holdout \
  --out work/tau2-telecom-holdout/report.json \
  --traces-dir work/tau2-telecom-holdout/sample-traces \
  --min-eligible 80 \
  --min-failures 30 \
  --min-failure-recall 0.99 \
  --max-false-alarm-rate 0.05 \
  --max-missed-failure-rate 0.0
```

For the prospective file, use `prospective-o4-mini-source.json` and change only
the result path, manifest path and the false-alarm threshold to `0.10`. A
changed task list, split algorithm, source result or manifest must fail closed.

前瞻文件使用 `prospective-o4-mini-source.json`，只替换结果路径、manifest 路径，并把误报
门槛改为 `0.10`。任务列表、分桶算法、结果文件或来源 manifest 任一变化都必须失败关闭。

## Interpretation / 解释边界

This is stronger than evaluating the complete public file because holdout task
IDs are disjoint from calibration task IDs. It is still not a fully independent
benchmark: both partitions come from the same published tau2-bench task family,
and the adapter was implemented with knowledge of that domain. The result is a
task-disjoint holdout proxy, not a universal unseen-domain or production
reliability claim.

它比整份公开文件复测更严格，因为 holdout 和 calibration 的任务 ID 完全不重叠。但两个分区
仍来自同一份公开 tau2-bench 任务族，适配器实现也知道该领域语义，因此只能称为“任务级留出
代理证据”，不能称为通用未见域泛化成绩或生产可靠性证明。

The split helper never reads `reward_info` while selecting a partition. Reward
is consulted only by the telecom evaluator after the Contract decision, and
the report records this boundary explicitly.

分桶 helper 在选择分区时不会读取 `reward_info`。reward 只在 Contract 做出判断后由电信评估器
读取，报告会明确记录这一边界。
