# v4.16 acceptance / v4.16 验收

v4.16 focuses on first-use integration, actionable diagnostics, readable
failure reports and a repeatable framework performance baseline. It does not
introduce a hosted control plane or claim a production SLA.

v4.16 聚焦首次接入、可执行诊断、可读失败报告和可重复的框架性能基线；不引入托管
控制台，也不宣称生产 SLA。

## Acceptance matrix

| Area | Evidence | Result |
| --- | --- | --- |
| Full core suite | `PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_*.py'` | See release CI run; all tests pass |
| First-use scaffold | `agent-regression init` in a clean temporary directory | Seeds baseline and candidate; `check` and normal `compare` exit 0 |
| Intentional regressions | Scaffold variants `wrong-resource`, `skip-tool`, `misread-result` | Each compare exits 1 |
| Actionable preflight | `check` emits `guidance` and `next_actions` | Missing Contract, relaxed paths and missing state evidence are explained without changing gate semantics |
| Actionable report | Compare JSON/Markdown includes `next_actions` | Blocking categories map to a concrete next step |
| Performance | `performance run` and `performance gate` | Small/medium workloads, environment and thresholds are recorded |
| Independent upgrade | [agent-regression-pilot](https://github.com/ANTAO94/agent-regression-pilot), release snapshot `8ebc38f`, post-release v4.16 verification `69028e5` | v4.15.0 snapshot and v4.16.0 follow-up both use a released wheel only; normal exit 0 and 3 injected errors exit 1 |
| Package install | Release workflow builds wheel/sdist and installs in a clean environment | CLI, benchmark, performance and bundled docs are available |

## First-use proxy run

The maintainer ran the generated project without importing the core checkout:

```text
init → check → compare(normal) = 0
compare(wrong-resource) = 1
compare(skip-tool) = 1
compare(misread-result) = 1
```

On the development host (CPython 3.9.6, macOS arm64), the full generator
completed 10,000 small traces at about 16,781 traces/s and 1,000 medium traces
at about 5,355 traces/s. These are a reproducibility sample, not a cross-host
SLA; the JSON report contains the environment needed for a like-for-like gate.

This is an automated clean-room proxy, not a claim that an uninvolved human
completed the 30/60/90-minute usability study. A real external user session is
still a follow-up item; the generated `AGENT_REGRESSION.md` and the independent
consumer repository make that session reproducible.

After the release snapshot, the independent consumer was upgraded to the
v4.16.0 wheel at commit `69028e5`; its GitHub Actions run passed the same normal
and three intentional-regression checks. This is an additional released-wheel
compatibility check, not a claim of universal framework coverage.

## Performance boundary

The performance report measures deterministic Trace validation/comparison only.
It is suitable for detecting a large framework regression on like-for-like
hardware. It is not evidence about model quality, tool-server latency, Agent
planning quality or production concurrency capacity.

## Release limitations

- The independent consumer is one small two-tool project, not universal
  framework compatibility.
- The v4.14/v4.15 τ² result remains calibration evidence because historical
  labels influenced rule design; it is not held-out generalization.
- Baselines remain human-owned; CI never accepts a candidate automatically.
- No hosted multi-user UI, access control, database or production SLA is part
  of v4.16.
