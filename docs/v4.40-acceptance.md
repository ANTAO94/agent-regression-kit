## Scope / 范围

- Revalidate approved positive/negative Trace and report references, run IDs,
  definition hashes and recomputed outcomes; reject stale or fabricated reviews.
- Preserve independent violations alongside evidence gaps without treating
  missing evidence as proof of business failure.
- ExecutionRecord allocates an ID before a callback, requires callback-bound
  output, records actual timestamps and binds code/input/environment metadata.
- Resolution recomputes failed-before and passed-after under one approved
  definition, requires a new execution, checks fixed premises and preserves an
  immutable, revalidatable chain.
- HelpPilot installed-wheel demonstration covers five controlled defects,
  allowed wording noise, fresh recovery, closure, suite and readable reports.
- Historical toolkit-adapter reproduction uses exact Git revisions and one
  fixed input/Contract to demonstrate a repaired false negative.

新增用例审核证据复核、实际执行记录、问题关闭、完整 HelpPilot 演练和自身历史漏报复现。

## Evidence boundary / 证据边界

- Callback and reviewer identities are caller declarations. Hashes and CI
  correlations detect inconsistency; they do not authenticate an adversarial
  producer or establish business truth.
- HelpPilot uses a real pinned external graph but deterministic model/retrieval
  substitutes and demo data. Recovery is `injected_recovery`, not an upstream
  bug fix or production refund.
- The historical defect belongs to this toolkit's adapter. Old incorrect
  claims passed; corrected claims now fail the unchanged Contract. This
  pass-to-fail transition is detector repair, not an Agent recovery closure.
- Without a before ExecutionRecord, closure requires fixed Case input and
  environment references and reports the missing old runtime provenance.
- Online traffic, external maintainers adopting the kit, unseen business
  generalization, human-label agreement, and a novice usability study remain
  unverified. No percentage maturity or production benefit is inferred.
- A successful self-test workflow is not a required merge check. Repository
  branch protection must be configured separately. On 2026-09-23 the GitHub
  branch API returned `protected: false` for main; this release does not change
  repository protection settings.

技术闭环不等于业务闭环：本轮证明运行、审核、比较和关闭证据可以串起来；尚不能
证明独立团队持续使用、线上质量或业务收益。不把测试数量换算成成熟度百分比。
