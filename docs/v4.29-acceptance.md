# v4.29 acceptance / v4.29 验收

## Scope / 范围

v4.29 adds an explicit boundary for repeated sampling evidence produced by a
real Agent or provider integration. The framework does not call a provider in
this feature. The caller records redacted `AgentTrace` files, writes a manifest
with non-secret provenance and asks the framework to evaluate the bundle with
the existing Contract and stability rules.

v4.29 增加了真实 Agent 或供应商接入的重复采样证据边界。这个版本不会由框架直接调用供应商；
接入方负责录制脱敏后的 `AgentTrace`，创建包含非敏感 provenance 的 manifest，再由框架使用
已有 Contract 和 stability 规则评估整组证据。

This separation is intentional: an API key, raw prompt, authorization header
or full provider response must not become part of a checked-in study report.
The result describes the observed sample and its uncertainty; it does not
infer a population reliability rate or prove that the Contract is complete.

这种分离是有意的：API Key、原始 Prompt、Authorization header 或完整供应商响应不应进入提交的
研究报告。结果描述的是已观察样本及其不确定性，不推断总体可靠率，也不证明 Contract 完整。

## Manifest / manifest 格式

```json
{
  "schema_version": "0.1",
  "study_id": "order-provider-sampling",
  "baseline": "baseline.trace.json",
  "runs": [
    {"id": "run-001", "trace": "runs/run-001.trace.json"},
    {"id": "run-002", "trace": "runs/run-002.trace.json"}
  ],
  "provenance": {
    "provider": "provider-name",
    "model": "model-name",
    "adapter": "framework-adapter",
    "study_id": "order-provider-sampling",
    "input_sha256": "<64 hex characters>",
    "tool_schema_sha256": "<64 hex characters>",
    "dataset_revision": "dataset-commit-or-version",
    "parameters": {"temperature": 0.2, "seed": 7}
  },
  "comparison_policy": {
    "final_answer_mode": "claims-only",
    "contract": {
      "required_claims": ["final_answer.claims.order_status"],
      "must_call": [{"tool": "get_order"}],
      "must_not_call": [{"tool": "refund_order"}],
      "max_steps": 2
    }
  },
  "policy": {"min_runs": 30}
}
```

The manifest and all referenced Trace files must stay under the manifest
directory. Every run ID must equal its Trace `run_id`, and duplicate IDs are
rejected. `input_sha256` and `tool_schema_sha256` can be created without
persisting the original objects:

```python
from agent_regression import canonical_sha256

input_hash = canonical_sha256({"messages": [{"role": "user", "content": "..."}]})
schema_hash = canonical_sha256({"tools": ["get_order", "refund_order"]})
```

The provenance validator rejects keys that look like credentials or secrets.
The JSON report contains only the public identifiers, hashes, Contract/policy
decision and per-run counts/paths; it does not embed the loaded Trace bodies.

manifest 和所有引用的 Trace 必须位于 manifest 目录内。每个 run ID 必须等于对应 Trace 的
`run_id`，重复 ID 会被拒绝。`input_sha256` 和 `tool_schema_sha256` 可以使用
`canonical_sha256` 生成，不需要把原始对象保存到研究报告中。provenance 校验器会拒绝看起来像
凭据或 secret 的字段。JSON 报告只包含公开标识、哈希、Contract/policy 决策以及每次运行的计数和
路径，不嵌入加载到的 Trace 原文。

## CLI / 命令

Generate and run the deterministic project-owned example:

```bash
python examples/sampling-study/create_demo_study.py \
  --out-dir work/order-123-study
agent-regression study \
  --manifest work/order-123-study/study.json \
  --format markdown \
  --out work/order-123-study/report.md
```

The command returns exit code `0` only when every recorded run satisfies the
comparison and the declared minimum sample/policy thresholds. It returns `1`
for a Contract difference, failed run, path variation or insufficient sample.

运行项目自带的确定性示例：

```bash
python examples/sampling-study/create_demo_study.py \
  --out-dir work/order-123-study
agent-regression study \
  --manifest work/order-123-study/study.json \
  --format markdown \
  --out work/order-123-study/report.md
```

只有每次运行都满足比较结果和声明的最低样本/策略门槛时才返回退出码 `0`；Contract 差异、
运行失败、路径变化或样本不足时返回 `1`。

## API / Python API

```python
from agent_regression import evaluate_sampling_study

report = evaluate_sampling_study("work/order-123-study/study.json")
assert report.to_dict()["report_type"] == "agent_sampling_study"
print(report.to_dict()["provenance"]["model"])
```

The public objects are `SamplingProvenance`, `SamplingStudyReport`,
`canonical_sha256` and `evaluate_sampling_study`. `StabilityReport` remains
backward compatible; the study report adds provenance and a manifest digest on
top of the same repeated-run metrics and Wilson intervals.

公开对象包括 `SamplingProvenance`、`SamplingStudyReport`、`canonical_sha256` 和
`evaluate_sampling_study`。`StabilityReport` 保持向后兼容；study 报告只是在相同的重复运行指标和
Wilson 区间上增加 provenance 与 manifest digest。

## Boundaries / 边界

- The feature evaluates recorded evidence; it does not own provider execution,
  sampling design, account isolation or correctness of the Contract.
- A 30-run minimum is an evidence policy, not a universal statistical-power
  calculation.
- Hashes identify hidden inputs and schemas; they do not prove that the hidden
  content was correct or representative.
- Provider/model metadata is provenance, not a quality score. Do not compare
  scores across providers without a reviewed task design and equivalent data.

- 这个功能评估已录制证据，不负责供应商执行、采样设计、账号隔离或 Contract 正确性。
- 30 次最低样本是证据策略，不是普适的统计功效计算。
- 哈希只能标识隐藏输入和 schema，不能证明隐藏内容正确或具有代表性。
- provider/model 元数据只是 provenance，不是质量分数；没有经过审核的任务设计和等价数据时，
  不要横向比较不同供应商的分数。
