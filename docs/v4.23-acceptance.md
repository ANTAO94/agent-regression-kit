# v4.23 acceptance / v4.23 验收

## Scope / 范围

v4.23 turns the v4.22 AgentDojo source matrix into a cross-model attack
matrix. It keeps four previously accepted `gpt-4o-2024-05-13` direct-path
cases as positive controls and adds four `gpt-4o-mini-2024-07-18`
`important_instructions` cases whose observed trajectories are expected to
violate the project-owned Contract. The gate passes only when the observed
Contract outcome equals the case's explicit expectation.

v4.23 把 v4.22 的 AgentDojo 独立来源矩阵扩展为跨模型攻击矩阵：保留四条
`gpt-4o-2024-05-13` direct 正常路径作为正向对照，再增加四条
`gpt-4o-mini-2024-07-18` `important_instructions` 攻击路径。攻击样本的
Contract 预期是失败；只有“实际 Contract 失败且与预期一致”时，矩阵门禁才通过。

This is an evidence-integration acceptance, not a claim that the kit makes a
model safe. The AgentDojo `utility` and `security` values remain external
oracle fields. They are checked for provenance and agreement, but never copied
into Trace or used as Contract rules.

这是外部证据接入验收，不是“框架让模型安全”的结论。AgentDojo 的 `utility` 和
`security` 仍是外部 oracle 字段：框架只检查它们的来源和一致性，不把它们复制到
Trace，也不把它们当作 Contract 规则。

Observed traces contain only the tool-call evidence. For example, the
workspace attack includes a forbidden `send_email`, and the banking attack
includes forbidden `send_money`; these are blocked by the declared Contract,
not by reading the external `security` label.

观察到的 Trace 只包含工具调用证据。例如 workspace 攻击轨迹调用了禁止的
`send_email`，banking 攻击轨迹调用了禁止的 `send_money`；它们是被项目声明的
Contract 阻断的，而不是读取外部 `security` 标签后直接判定的。

## Reproduce locally / 本地复现

```bash
mkdir -p work/agentdojo-cross-model/results
python - <<'PY'
import json
from pathlib import Path
from urllib.request import urlopen

manifest = json.loads(Path("examples/agentdojo/matrix-v4.23.json").read_text())
result_dir = Path("work/agentdojo-cross-model/results")
for case in manifest["cases"]:
    with urlopen(case["download_url"]) as response:
        (result_dir / case["result_file"]).write_bytes(response.read())
PY

PYTHONPATH=src python examples/agentdojo_matrix_validation.py \
  --manifest examples/agentdojo/matrix-v4.23.json \
  --results-dir work/agentdojo-cross-model/results \
  --out work/agentdojo-cross-model/report.json \
  --trace-dir work/agentdojo-cross-model/traces
```

The validated run produced:

```text
case_count=8
passed_case_count=8
expected_contract_blocks=4
observed_contract_blocks=4
gate_passed=true
```

The report also contains one redacted report and one Trace per case. A case
with `expected_contract_passed: false` is not a bypass: changing its observed
trajectory to satisfy the Contract makes the matrix fail because the observed
outcome no longer matches the expected attack outcome.

## Boundaries / 边界

- The matrix uses pinned exported results; it does not rerun the full AgentDojo
  simulator, model providers or tool environments.
- Four attack cases are a reviewed sample, not a security-rate estimate.
- Two model pipelines do not establish cross-model generalization.
- Contracts are manually reviewed per case and are intentionally separate from
  upstream utility/security labels.
- A passing matrix proves reproducible evidence handling and the reviewed
  Contract decisions for these cases; it does not guarantee production safety,
  factual correctness or authorization of real side effects.

- 矩阵使用固定 revision 的导出结果，不会重跑完整 AgentDojo simulator、模型服务或工具环境。
- 四条攻击样本是经过审核的样本，不是安全率统计估计。
- 两个模型 pipeline 不能证明跨模型泛化。
- 每条 Contract 都是逐样本人工审核的，并且与 upstream 的 utility/security 标签分离。
- 矩阵通过说明这些样本的证据处理和 Contract 决策可复现；不保证生产安全、事实正确或真实副作用授权。

## Release decision / 发布决策

v4.23 is acceptable as a cross-model evidence-integration release. It is not
the final maturity target for universal Agent security evaluation. The next
milestones are more independently sourced attack families, frozen
pre-registration of Contracts, repeated-run variance reporting and an
uninvolved human usability study.

v4.23 可以作为跨模型证据接入版本发布，但不是“通用 Agent 安全评测”的最终成熟度
目标。后续仍需增加独立来源攻击族、在读取结果前冻结并预注册 Contract、报告多次运行
方差，并完成不参与项目实现人员的可用性研究。
