# Agent Regression Kit v4.1 Acceptance / v4.1 验收说明

v4.1 extends the v4.0 compatibility contract with stricter evidence validation
and direct adapters for three real Agent frameworks. Public API generation 4,
AgentTrace schema 0.1 and report schema 0.1 remain unchanged.

v4.1 在 v4.0 兼容契约上增加更严格的证据校验，以及三个真实 Agent 框架的
直接适配。公共 API 代际仍为 4，AgentTrace 与报告 schema 仍为 0.1。

## 1. Release scope / 发布范围

| Area / 范围 | v4.1 requirement / v4.1 要求 |
| --- | --- |
| Evidence gates / 证据门禁 | Empty batch and coverage inputs fail closed instead of producing a green result / 空批次和空覆盖输入必须失败，不能产生假绿色 |
| Trace validation / Trace 校验 | Reject unknown fields, invalid event types, malformed sequence values and reused call IDs / 拒绝未知字段、错误类型、非法序号和重复调用 ID |
| Policy validation / 策略校验 | Reject unknown nested assertion, normalizer, tool, path and side-effect fields / 拒绝嵌套断言、归一化、工具、路径和副作用规则中的拼写错误 |
| Report trust / 报告可信度 | Reject unknown explicit report types and non-boolean pass status / 拒绝未知报告类型以及非布尔 passed 值 |
| Non-determinism / 非确定性 | Normalize run-scoped call IDs and apply contract noise rules to stability claims / 归一化运行级调用 ID，稳定性 claims 使用同一套噪声规则 |
| Frameworks / 框架 | Convert completed PydanticAI, OpenAI Agents SDK and LangGraph runs into validated AgentTrace / 将三种框架的真实运行转换为合法 AgentTrace |

## 2. Real framework gate / 真实框架门禁

The optional framework job installs current compatible major versions on
Python 3.11 and runs deterministic, credential-free Agents through the real
framework runtimes:

```bash
python -m pip install '.[frameworks]'
python examples/pydantic_ai_agent_example.py
python examples/openai_agents_agent_example.py
python examples/langgraph_agent_example.py
```

Each generated Trace must pass `agent-regression validate`. PydanticAI and
OpenAI Agents traces must compare equal, as must OpenAI Agents and LangGraph.

可选框架任务会在 Python 3.11 中安装兼容的当前主版本，并使用真实框架运行时、
确定性本地模型和固定工具执行三个 Agent；不需要模型 API Key。生成的 Trace
必须全部通过校验，并且同一业务场景在三种框架之间比较一致。

## 3. Negative regression proof / 反向回归证明

CI must also run a deliberately broken LangGraph Agent. The user still asks
for order 123, while the Agent calls `get_order(order_id="456")`:

```bash
AGENT_TOOL_ORDER_ID=456 \
AGENT_TRACE_OUT=work/langgraph-parameter-regression.trace.json \
python examples/langgraph_agent_example.py
```

Comparing this candidate with the reviewed order-123 baseline must exit with
status 1 and report the changed tool argument and tool result. A workflow that
only generates valid JSON but cannot reject this case does not satisfy v4.1.

CI 还必须运行一个故意出错的 LangGraph Agent：用户仍查询订单 123，但 Agent
错误调用订单 456。与审核后的订单 123 baseline 比较时必须以退出码 1 失败，
并报告工具参数和结果差异。只能生成 JSON、却拦不住该错误的实现不满足 v4.1。

## 4. Compatibility / 兼容性

- Python 3.9 remains supported by the dependency-free core.
- Real framework extras require Python 3.10 or newer because of upstream
  framework requirements.
- Existing v4.0 AgentTrace, contracts, configs, reports and baselines remain
  readable; no baseline or schema migration is required.
- Unknown fields that were previously ignored may now fail validation. Fix the
  spelling or remove the unsupported field; do not weaken validation to retain
  accidental behavior.

- 无第三方依赖的核心仍支持 Python 3.9。
- 真实框架可选依赖因上游要求需要 Python 3.10 或更高版本。
- 现有 v4.0 Trace、Contract、配置、报告和 baseline 无需迁移。
- 以前被静默忽略的未知字段现在可能校验失败；应修正拼写或删除不支持字段。

## 5. Release evidence / 发布证据

A v4.1 release is complete only when all of the following pass:

1. The complete offline test suite on the supported core Python matrix.
2. Real-framework positive comparisons and the negative parameter-regression
   assertion.
3. Source distribution and wheel build.
4. Clean-wheel installation and CLI smoke tests.
5. Presence of this document and the bilingual framework guide in the wheel.
6. `git diff --check` and a clean tagged release commit.

v4.1 发布必须通过完整离线测试、真实框架正反例、源码包与 wheel 构建、干净
环境安装、文档打包检查以及干净的 tag 提交。v4.0 的安全边界继续适用，详见
[v4.0 acceptance](v4-acceptance.md)。
