# v4.34 acceptance / v4.34 验收

## Scope / 范围

v4.34 adds an optional report-handoff integrity boundary to `study`. After the
CLI renders the final JSON, Markdown or JUnit report to `--out`,
`--checksum-out` writes a conventional SHA-256 sidecar over those exact bytes.
This makes an uploaded CI artifact or audit attachment independently
verifiable without changing the study manifest, Trace schema or public API
version.

v4.34 为 `study` 增加可选的报告交接完整性边界。CLI 将 JSON、Markdown 或 JUnit 报告写入 `--out` 后，
`--checksum-out` 会针对最终报告的实际字节写出标准 SHA-256 sidecar。这样 CI artifact 或审计附件可以
被独立复核，同时不改变 study manifest、Trace schema 和公共 API 版本。

The sidecar detects replacement during handoff. It is not a signature, provider
attestation, semantic correctness proof or generalization result.

sidecar 能发现交接过程中的文件替换，但不是数字签名、供应商 attestation、业务语义正确性证明或泛化结果。

## CLI contract / CLI 契约

```bash
agent-regression study \
  --manifest work/order-123-study/study.json \
  --format markdown \
  --out work/order-123-study/report.md \
  --checksum-out work/order-123-study/report.md.sha256
```

The sidecar contains exactly one line:

```text
<64 lowercase hexadecimal SHA-256>  report.md
```

`--checksum-out` requires `--out`. Without a concrete output file there is no
stable byte stream to hash, so the CLI fails closed rather than claiming that a
stdout stream was protected. Existing calls without the flag behave exactly as
before.

sidecar 正好包含一行 `<64 位小写十六进制 SHA-256>  report.md`。`--checksum-out` 必须和 `--out` 一起使用；
如果只有 stdout，就没有稳定的待摘要字节流，因此 CLI 会 fail closed，不会假装保护了 stdout。没有该参数的旧调用
行为保持不变。

The flag applies to all three study renderers:

| Format | Output | Sidecar |
| --- | --- | --- |
| `json` | exact JSON bytes | supported |
| `markdown` | exact Markdown bytes | supported |
| `junit` | exact JUnit XML bytes | supported |

## Local acceptance / 本地验收

The v4.34 source tree passes **287 tests** with `PYTHONPATH=src`. The added
test renders a study report, computes its SHA-256 independently and verifies
that the sidecar has the expected filename and digest. Existing study,
manifest, evidence-binding and CI tests remain green.

v4.34 源码树在 `PYTHONPATH=src` 下通过 **287 项测试**。新增测试会真实生成 study 报告，独立计算报告
SHA-256，并校验 sidecar 中的文件名和摘要；既有 study、manifest、evidence binding 和 CI 测试全部保持通过。

The following negative invocation is also part of the contract:

```bash
set +e
agent-regression study \
  --manifest work/order-123-study/study.json \
  --checksum-out work/order-123-study/report.sha256
test "$?" -eq 2
```

没有 `--out` 的负向调用必须返回 `2`，因为 sidecar 不能绑定一个不可复核的 stdout。

## Compatibility / 兼容性

- v4.33 and earlier study manifests remain valid.
- `PUBLIC_API_VERSION=4` is unchanged.
- Trace, Contract, Report and study schema versions are unchanged.
- The option is only a report-output feature; it does not add credentials,
  network access or provider execution.

- v4.33 及更早的 study manifest 继续兼容。
- `PUBLIC_API_VERSION=4` 不变。
- Trace、Contract、Report 和 study schema 版本不变。
- 该参数只影响报告输出，不增加凭据、网络访问或供应商执行。

## Release boundary / 发布边界

The immutable tag, release asset digests, GitHub Actions runs and independent
consumer verification are appended after the v4.34 release workflow completes.
They must be copied from remote workflow/release results, not inferred from a
local build.

不可变 tag、发布资产摘要、GitHub Actions run 和独立 consumer 验证，会在 v4.34 发布工作流完成后补入；
这些数据必须来自远程 workflow/release 结果，不能用本地构建推断。

## Boundary / 边界

The sidecar proves only that the report bytes presented to a reviewer match the
bytes that were hashed. Reviewers still need to inspect the manifest, evidence
index, Contract, sample size and limitations. Human usability research and
unseen-task generalization remain external validation requirements.

sidecar 只证明交给审核者的报告字节与摘要对应。审核者仍需检查 manifest、evidence index、Contract、样本量
和限制说明；真实用户易用性研究与未见任务泛化仍然是框架外的验收要求。
