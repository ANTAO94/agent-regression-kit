# v4.31 acceptance / v4.31 验收

## Scope / 范围

v4.31 extends v4.30 file integrity into an explicit evidence index. A study
manifest can declare small, non-secret source descriptors for the input,
tool-schema, adapter, dataset, environment or provider output used to create
the recorded traces. The evaluator validates every entry's role, path and
SHA-256 before evaluating the study, then writes only the index metadata to the
report.

v4.31 把 v4.30 的文件完整性扩展为显式的 evidence index。study manifest 可以声明生成 Trace
时使用的非敏感来源描述文件，例如 input、tool schema、adapter、dataset、environment 或
provider output。评估器会在评估 study 前校验每一项的角色、路径和 SHA-256，报告只写入索引元数据，
不会嵌入这些文件的原文。

This is a review boundary, not a semantic oracle. An evidence entry says
which artifact was used and whether it changed; it does not prove that the
artifact itself is correct, representative or sufficient.

这是审计边界，不是语义裁判。evidence 条目只能说明“使用了哪个来源文件以及它是否被修改”，不能
证明该来源本身正确、具有代表性或足够覆盖业务不变量。

## Manifest / manifest 格式

The existing v4.30 `integrity` fields remain valid. v4.31 adds an optional
`evidence` list and can require particular roles:

v4.30 已有的 `integrity` 字段继续有效。v4.31 增加可选的 `evidence` 列表，并且可以要求必须
出现指定角色：

```json
{
  "schema_version": "0.1",
  "study_id": "order-provider-sampling",
  "baseline": "baseline.trace.json",
  "runs": [
    {
      "id": "run-001",
      "trace": "runs/run-001.trace.json",
      "sha256": "<trace-sha256>"
    }
  ],
  "evidence": [
    {
      "id": "input-descriptor",
      "role": "input",
      "path": "evidence/input.json",
      "sha256": "<file-sha256>"
    },
    {
      "id": "adapter-descriptor",
      "role": "adapter",
      "path": "evidence/adapter.json",
      "sha256": "<file-sha256>"
    }
  ],
  "integrity": {
    "require_trace_hashes": true,
    "require_evidence_index": true,
    "required_evidence_roles": ["adapter", "input"]
  }
}
```

Supported roles are `input`, `tool_schema`, `adapter`, `dataset`, `environment`,
`provider_output` and `other`. IDs and paths must be unique; every path must be
relative to and contained by the manifest directory. A required role must occur
at least once. A mismatch or missing required role is invalid evidence and the
CLI returns status `2`.

支持的角色包括 `input`、`tool_schema`、`adapter`、`dataset`、`environment`、`provider_output`
和 `other`。ID 与路径必须唯一；所有路径必须是相对于 manifest 的目录内路径。要求的角色至少要
出现一次。摘要不匹配或缺少必需角色都属于无效证据，CLI 返回状态 `2`。

## Report / 报告

The report adds an `evidence_index` object without embedding source-file
contents:

报告新增 `evidence_index` 对象，但不会嵌入来源文件内容：

```json
{
  "required": true,
  "verified": true,
  "entry_count": 2,
  "roles": ["adapter", "input"],
  "entries": [
    {
      "id": "input-descriptor",
      "role": "input",
      "path": "evidence/input.json",
      "sha256": "..."
    }
  ]
}
```

`evidence_integrity.evidence_index_verified` mirrors the verification result
so report-index/history consumers can gate it without parsing source files.
Manifests from v4.30 and earlier without `evidence` remain backward compatible;
the report simply contains an empty optional index unless a manifest requires
one.

`evidence_integrity.evidence_index_verified` 会同步校验结果，方便 report-index/history 消费方
直接做门禁，不需要解析来源文件。v4.30 及更早的不带 `evidence` 的 manifest 继续兼容；如果
manifest 没有要求 evidence index，报告中的可选索引为空。

## CLI and CI / CLI 与 CI

The deterministic example now creates three descriptors (input, tool schema
and adapter), binds their hashes and requires all three roles:

项目确定性示例现在创建 input、tool schema、adapter 三个描述文件，绑定它们的哈希，并要求三个
角色全部存在：

```bash
python examples/sampling-study/create_demo_study.py \
  --out-dir work/order-123-study
agent-regression study \
  --manifest work/order-123-study/study.json \
  --format markdown \
  --out work/order-123-study/report.md
```

Core CI runs both evidence-negative cases: it changes a Trace and separately
changes the adapter descriptor in copied temporary bundles. Both commands must
return `2`; the checked-in study and normal report directory are not modified.

核心 CI 同时运行两类证据负向用例：在复制出的临时 bundle 中分别修改 Trace 和 adapter 描述文件，
两次命令都必须返回 `2`；仓库中的 study 和正常报告目录不会被修改。

## Boundaries / 边界

- The evidence index is a provenance inventory, not a signature system or a
  semantic correctness proof.
- The framework still does not execute online providers, inspect hidden prompts
  or decide whether an adapter's claims are truthful.
- Required roles are project policy; selecting `adapter` or `dataset` does not
  make the artifact complete.
- The report stores paths and digests, not raw source descriptors, prompts,
  credentials or provider responses.

- evidence index 是来源清单，不是签名系统，也不是语义正确性证明。
- 框架仍不会执行在线供应商、检查隐藏 Prompt，或判断 Adapter 的 claims 是否真实。
- 必需角色是项目策略；声明 `adapter` 或 `dataset` 不代表该来源已经完整。
- 报告只保存路径和摘要，不保存来源描述原文、Prompt、凭据或供应商响应。
