# v4.33 acceptance / v4.33 验收

## Scope / 范围

v4.33 extends the v4.32 semantic-binding boundary from input, tool-schema and
adapter identity to the identity that explains a sampling run: provider,
model and dataset revision. A study can now require these values to be read
from indexed, role-specific descriptor files rather than trusting only the
top-level manifest fields.

v4.33 将 v4.32 的语义绑定边界从 input、tool schema 和 adapter 扩展到解释一次采样运行所必需的
provider、model 和 dataset revision。study 可以要求这些值分别来自 evidence index 中带有明确 role
的描述文件，而不是只相信 manifest 顶层字段。

This is an explicit consistency check, not an external truth oracle. It does
not call a provider, inspect hidden prompts, attest to a model vendor or prove
that a dataset revision is representative. It only prevents a study bundle
from silently mixing declarations from different runs.

这仍然是显式一致性检查，不是外部真实性裁判。它不会调用供应商、读取隐藏 Prompt、证明模型供应商的声明，
也不会证明数据版本具有代表性；它解决的是 study bundle 把不同运行的声明静默混在一起的问题。

## Manifest / manifest 格式

The three v4.33 targets are added to the existing v4.32 binding mechanism:

v4.33 在 v4.32 的 binding 机制上增加三个 target：

| Target | Required role | Field read from descriptor |
| --- | --- | --- |
| `provenance.provider` | `provider_output` | `provider` |
| `provenance.model` | `provider_output` | `model` |
| `provenance.dataset_revision` | `dataset` | `dataset_revision` |

The demo also retains the v4.32 targets. Its complete binding target set is:

示例同时保留 v4.32 的 target，因此完整绑定集合为：

```text
provenance.input_sha256
provenance.tool_schema_sha256
provenance.adapter
provenance.provider
provenance.model
provenance.dataset_revision
```

The relevant manifest shape is:

```json
{
  "provenance": {
    "provider": "fixture-provider",
    "model": "fixture-model-v1",
    "input_sha256": "<input-sha256>",
    "tool_schema_sha256": "<tool-schema-sha256>",
    "adapter": "recorded-trace-import",
    "dataset_revision": "local-fixture-v1"
  },
  "evidence": [
    {"id": "provider_output-descriptor", "role": "provider_output", "path": "evidence/provider-descriptor.json", "sha256": "<file-sha256>"},
    {"id": "model_output-descriptor", "role": "provider_output", "path": "evidence/model-descriptor.json", "sha256": "<file-sha256>"},
    {"id": "dataset-descriptor", "role": "dataset", "path": "evidence/dataset-descriptor.json", "sha256": "<file-sha256>"}
  ],
  "evidence_bindings": [
    {"evidence_id": "provider_output-descriptor", "target": "provenance.provider", "field": "provider"},
    {"evidence_id": "model_output-descriptor", "target": "provenance.model", "field": "model"},
    {"evidence_id": "dataset-descriptor", "target": "provenance.dataset_revision", "field": "dataset_revision"}
  ],
  "integrity": {
    "require_evidence_index": true,
    "required_evidence_roles": ["adapter", "dataset", "input", "provider_output", "tool_schema"],
    "require_evidence_bindings": true,
    "required_evidence_bindings": [
      "provenance.adapter",
      "provenance.dataset_revision",
      "provenance.input_sha256",
      "provenance.model",
      "provenance.provider",
      "provenance.tool_schema_sha256"
    ]
  }
}
```

The evidence index remains the file-identity boundary. The evaluator first
checks each descriptor SHA-256, then parses only the declared JSON field and
compares it with the corresponding provenance value. A changed field with a
refreshed file digest still fails semantic validation when it no longer
matches provenance. Missing role, wrong role, duplicate evidence identity or
unsupported target returns CLI status `2`.

evidence index 继续负责文件身份边界。评估器先校验每个描述文件的 SHA-256，再只读取声明的 JSON 字段，
与对应 provenance 值比较。即使修改字段后同步刷新文件摘要，只要不再与 provenance 匹配，仍然会被语义校验
阻断。缺少 role、role 错误、证据身份重复或 target 不支持时，CLI 返回状态 `2`。

## Report / 报告

The successful deterministic demo reports six bindings and five evidence
roles without copying any descriptor contents:

确定性示例的成功报告包含六条 binding 和五种 evidence role，但不会复制描述文件原文：

```json
{
  "evidence_index": {
    "entry_count": 6,
    "roles": ["adapter", "dataset", "input", "provider_output", "tool_schema"]
  },
  "evidence_bindings": {
    "required": true,
    "verified": true,
    "binding_count": 6,
    "targets": [
      "provenance.adapter",
      "provenance.dataset_revision",
      "provenance.input_sha256",
      "provenance.model",
      "provenance.provider",
      "provenance.tool_schema_sha256"
    ]
  },
  "evidence_integrity": {
    "evidence_index_verified": true,
    "evidence_bindings_verified": true
  }
}
```

The report is content-free by design: reviewers can see which identities were
verified, while sensitive provider output and raw prompts remain outside the
report boundary.

报告有意保持 content-free：审核者能看到哪些身份被验证，但敏感的供应商输出和原始 Prompt 不会进入报告。

## Reproduce locally / 本地复现

```bash
python examples/sampling-study/create_demo_study.py \
  --out-dir work/order-123-study
agent-regression study \
  --manifest work/order-123-study/study.json \
  --format markdown \
  --out work/order-123-study/report.md
```

The command exits `0` for the matching fixture. To demonstrate the semantic
gate, change `evidence/provider-descriptor.json` to another provider, refresh
only that evidence entry's file digest and run the command again. It must exit
`2` with an evidence-binding mismatch rather than evaluating stale evidence.

匹配的 Fixture 返回 `0`。要验证语义门禁，可以把 `evidence/provider-descriptor.json` 改成另一个
provider，只更新该 evidence entry 的文件摘要，再次执行命令；命令必须返回 `2`，而不是继续评估过期或
错配的证据。

## Local acceptance / 本地验收

The v4.33 source tree passes **286 tests** with `PYTHONPATH=src`. Focused
coverage includes v4.32 manifest compatibility, six binding targets, role and
field validation, descriptor redaction, the deterministic study generator,
hash-refresh semantic mismatch and CI workflow assertions.

v4.33 源码树在 `PYTHONPATH=src` 下通过 **286 项测试**。专项覆盖 v4.32 manifest 兼容、六个 binding
target、role/field 校验、描述文件脱敏、确定性 study 生成、刷新哈希后的语义错配和 CI 工作流断言。

## Release and independent consumer / 发布与独立消费

The release and consumer values are filled after the immutable v4.33 tag,
release assets and independent consumer workflow complete. They are part of
the release acceptance, not claims inferred from the local source tree.

不可变 v4.33 tag、发布资产和独立 consumer workflow 完成后，才会把 release 与 consumer 的 commit、run
和 SHA-256 填入这里。这些字段必须来自远程验收，不会用本地源码测试结果代替。

## Compatibility and boundaries / 兼容与边界

- v4.32 and earlier manifests that do not require the new targets remain valid.
- `require_evidence_bindings` still requires `require_evidence_index`.
- `provider` and `model` intentionally use separate `provider_output` entries;
  this prevents one descriptor from silently serving two identities.
- The new layer proves declaration consistency, not provider attestation,
  model quality, dataset representativeness, human usability or unseen-task
  generalization.

- 不要求新 target 的 v4.32 及更早 manifest 继续兼容。
- `require_evidence_bindings` 仍然要求同时开启 `require_evidence_index`。
- `provider` 和 `model` 有意使用两个独立的 `provider_output` 条目，避免一个描述文件悄悄承担两种身份。
- 新边界证明的是声明一致性，不是供应商证明、模型质量、数据集代表性、真实用户易用性或未见任务泛化。
