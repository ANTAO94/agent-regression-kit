# Agent Regression Kit v4.2 Acceptance / v4.2 验收说明

v4.2 adds a credential-gated live model-provider check while preserving the
v4 public API generation and evidence schema 0.1. It extends deterministic
framework compatibility with one deliberately small paid DeepSeek check.

v4.2 在保持公共 API 代际 4 和证据 schema 0.1 不变的前提下，新增受密钥保护的
真实模型供应商检查。它在确定性框架兼容测试之外，增加一次刻意控制成本的 DeepSeek
付费验证。

## 1. Live Agent contract / 真实 Agent 契约

The live example must:

1. use `deepseek-flash`, non-thinking mode and a 64-token output cap;
2. force the first model turn to call `get_order` with the user-supplied ID;
3. execute only the local deterministic fixture, never a production tool;
4. convert the call, result and final structured claims into AgentTrace 0.1;
5. compare with the reviewed order-123 baseline in `claims-only` mode while
   keeping tools, arguments, results and claims strict;
6. reject missing credentials before making a network request.

真实示例必须使用 `deepseek-flash`、关闭思考模式、把输出限制为 64 tokens；第一轮
必须调用 `get_order`，只执行本地确定性 Fixture，并将调用、结果和结构化结论转换
为 AgentTrace 0.1。最终文字允许变化，但工具、参数、结果和 claims 必须严格一致。

## 2. Credential boundary / 密钥边界

- The API key is accepted only through the `DEEPSEEK_API_KEY` environment
  variable or an explicit in-memory argument.
- The key must never enter Trace metadata, reports, fixtures, documentation,
  command output, uploaded artifacts or Git history.
- GitHub Actions reads the key only from the encrypted repository secret named
  `DEEPSEEK_API_KEY`.
- The workflow scans generated JSON artifacts for the active secret before
  upload.

- API Key 只能通过 `DEEPSEEK_API_KEY` 环境变量或内存参数传入。
- 密钥不得进入 Trace、报告、Fixture、文档、命令输出、上传产物或 Git 历史。
- GitHub Actions 只能从同名加密仓库 Secret 读取。
- 上传产物前必须扫描并确认其中不含当前密钥。

## 3. Cost boundary / 成本边界

The default live run makes two short requests: one tool-selection response and
one final JSON answer. Thinking is disabled. The scheduled workflow runs once
per week on Sunday, outside the provider's documented weekday peak windows.
No automatic retry is performed because retrying an uncertain paid request can
duplicate cost.

默认真实检查只发起两次短请求：一次选择工具，一次生成最终 JSON。关闭思考，不做
自动重试；定时任务每周日运行一次，避开官方列出的工作日峰值窗口。模型和价格属于
外部状态，维护者必须定期复核官方定价说明。

## 4. Required evidence / 必需证据

A v4.2 release requires:

- all offline unit and integration tests;
- a local live run that produces a valid three-event Trace;
- zero blocking differences against the reviewed baseline;
- recorded token usage and a manual cost estimate;
- a successful manually dispatched GitHub live-provider workflow;
- the existing Python matrix, framework matrix, wheel build and clean-install
  release gates.

v4.2 发布必须具备完整离线测试、一次本地真实调用、合法的三事件 Trace、baseline
零阻断差异、token 与成本记录、手动触发成功的 GitHub 真实供应商工作流，以及既有
Python/框架矩阵、wheel 和干净安装门禁。

See [DeepSeek live provider check](deepseek-live.md) for operating instructions
and [v4.1 acceptance](v4.1-acceptance.md) for the inherited framework gates.
