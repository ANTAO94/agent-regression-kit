validation. The goal is not to make replay permissive; it is to reduce false
alarms only where an explicit business outcome relation has been declared.

显式声明业务结果关系的地方降低误报。

## Evidence flow / 证据流

```text
pinned upstream JSON + SHA-256
        ↓
published messages → AgentTrace (reward excluded)
        ↓
task actions → outcome-aware ContractPolicy
        ↓
Contract decision (reward still hidden)
        ↓
external reward → confusion matrix
```

The adapter groups only task-declared alternatives. `payment_method_id` is
ignored only for grouping the declared payment alternatives; order/resource
arguments remain exact. Failed expected attempts and address repeats are
explicitly configured, while successful unexpected writes remain blocking.

适配器只归并任务定义中已经声明的替代动作。`payment_method_id` 只用于归并已声明的支付
选择，订单/资源参数仍然精确匹配。失败尝试和地址重复是显式配置的，未声明的成功写操作
仍然阻断。

## Local verification / 本地验证

```bash
mkdir -p work/tau2
curl --fail --location --retry 3 \
  --output work/tau2/results.json \
  "https://raw.githubusercontent.com/sierra-research/tau2-bench/v1.0.1/data/tau2/results/final/gpt-4.1-mini-2025-04-14_retail_base_gpt-4.1-2025-04-14_4trials.json"

echo "6d6badb43b716adca31591b0b40e15fd493b49adddaa8e2c47035bb557549257  work/tau2/results.json" \
  | shasum -a 256 -c -

PYTHONPATH=src python examples/tau2_retail_validation.py \
  --results work/tau2/results.json \
  --out work/tau2/report.json \
  --traces-dir work/tau2/sample-traces
```

The report is the source for the matrix above. The upstream reward is read
only after the Contract decision and is never embedded into Trace metadata,
claims or the Contract itself.

## Interpretation boundary / 解释边界

- This is measured evidence on one pinned public dataset, not a claim that
  τ²-bench adopts or endorses this project.
- The adapter covers the published half-duplex retail file and write-scenario
  oracle. It does not cover every τ²-bench domain, model or production workload.
- A zero false-alarm result here comes from explicit, reviewed equivalence rules;
  it does not justify ignoring identifiers, tenants, amounts or resources in a
  different project.
- `state_equivalence` does not infer equivalence from an LLM, tool description or
  similar names. New equivalence rules require a fixture and a negative case.

- 这是固定公开数据集上的实测证据，不代表 τ²-bench 采用或背书本项目；
- 适配器覆盖固定的半双工零售文件和写场景 oracle，不覆盖所有领域、模型和生产负载；
- 这里的 0 误报来自经过审核的显式等价规则，不能据此在其他项目中忽略订单号、租户、金额
  或资源标识；
- `state_equivalence` 不会根据 LLM、工具描述或相似名称自动推断等价；新增规则必须配套
  Fixture 和反例。
