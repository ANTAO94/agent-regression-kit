# Agent Regression Kit v4.3 Acceptance / v4.3 验收说明

v4.3 extends the hosted-model check from one tool to a deterministic two-tool
dependency chain. It preserves public API generation 4 and Trace schema 0.1.

v4.3 将在线模型检查从单工具扩展为确定性的两工具依赖链，同时保持公共 API
代际 4 与 Trace schema 0.1 不变。

## Scope / 验收范围

- `required_tool_sequence` requires one exact tool at each dependency step.
- The model generates arguments and must propagate values from prior results.
- `get_order` returns status and amount; `check_refund_eligibility` must receive
  those exact values.
- The final answer exposes four required claims: order ID, status, eligibility
  and refund amount.
- A wrong cross-step argument is blocked by structural comparison and Contract.
- Both live traces and reports are scanned for the active credential before
  artifact upload.

- `required_tool_sequence` 在每个依赖步骤要求一个确定工具。
- 参数仍由模型生成，模型必须正确传递前一步结果。
- `get_order` 返回状态和金额，退款资格工具必须收到完全一致的值。
- 最终答案必须给出订单号、状态、退款资格和退款金额四个 claims。
- 错误的跨步骤参数会同时被结构比较和 Contract 阻断。
- 上传产物前，工作流会扫描两份真实 Trace 与报告，确保当前密钥没有写入。

## Verified evidence / 已验证证据

The live run [DeepSeek provider #35485202922](https://github.com/ANTAO94/agent-regression-kit/actions/runs/35485202922)
passed both scenarios with zero differences. The multi-tool run recorded:

```text
get_order({"order_id":"123"})
  → {"status":"not_shipped","paid_amount":88}
check_refund_eligibility({"order_id":"123","order_status":"not_shipped","paid_amount":88})
  → {"eligible":true,"refund_amount":88}
```

Its three provider requests used 1,118 input tokens and 132 output tokens. This
is evidence for the tested model, prompt and fixture at that run; it is not a
claim of autonomous planning, all-model compatibility or production load
coverage.

真实运行同时通过单工具和多工具场景，差异数均为 0。多工具场景的三次请求使用
1,118 个输入 tokens 与 132 个输出 tokens。该结果只证明当次模型、Prompt 与
Fixture 的依赖传递正确，不代表自主规划、所有模型兼容或生产负载验证。
