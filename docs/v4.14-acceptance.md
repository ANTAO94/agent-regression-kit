# v4.14 acceptance / v4.14 验收

v4.14 adds the benchmark governance layer required before publishing a quality
number. A manifest binds the source revision, split definition, evidence,
Contract bundle, labels and package provenance with SHA-256. The decision step
cannot use label meaning; the score step validates the frozen decision digest
before reading labels.

v4.14 增加正式发布评测数字前所需的基准治理层。manifest 用 SHA-256 绑定数据源版本、数据拆分、
证据、Contract Bundle、标签和框架版本；decide 阶段不能使用标签语义，score 阶段先校验冻结的
decision digest，再读取标签。

## Commands / 命令

```bash
agent-regression benchmark prepare --manifest benchmark/manifest.json
agent-regression benchmark decide \
  --manifest benchmark/manifest.json \
  --out work/benchmark/decisions.json
agent-regression benchmark score \
  --manifest benchmark/manifest.json \
  --decisions work/benchmark/decisions.json \
  --out work/benchmark/score.json
```

The manifest is relative to its own directory. A minimal manifest binds four
JSON files:

```json
{
  "schema_version": "0.1",
  "benchmark_id": "retail-evaluation-v1",
  "source": {
    "repository": "https://github.com/owner/project",
    "revision": "v1.2.3",
    "data_path": "evidence.json",
    "data_sha256": "<64 hex characters>"
  },
  "split": {
    "name": "evaluation",
    "path": "split.json",
    "sha256": "<64 hex characters>"
  },
  "contract_bundle": {"path": "contracts.json", "sha256": "<64 hex characters>"},
  "evidence": {"path": "evidence.json", "sha256": "<64 hex characters>"},
  "labels": {"path": "labels.json", "sha256": "<64 hex characters>"},
  "agent_regression": {"version": "4.14.0", "commit": "<immutable commit>"}
}
```

`evidence.json` contains `samples` with `id`, `baseline` and `candidate` Trace
paths. `contracts.json` contains one `cases` entry for every sample ID and the
same `contract` shape accepted by normal compare. `labels.json` contains
`labels` with `sample_id` and boolean `passed` values.

`prepare` validates all hashes and Trace/Contract inputs, but does not use the
labels to make a decision. `decide` produces only `pass`, `block` or
`unsupported` decisions and an internal `decision_digest`. `score` rejects a
changed digest, incomplete sample coverage, unknown labels and moving source
revisions. Unsupported samples remain in the denominator report as an explicit
count and are not silently deleted.

`prepare` 会校验所有哈希以及 Trace/Contract 输入，但不会用标签作判断。`decide` 只输出
`pass`、`block` 或 `unsupported` 及内部 `decision_digest`。`score` 会拒绝被修改的 digest、
不完整的样本覆盖、未知标签和可变数据版本。unsupported 样本会在报告中单独计数，不会被静默
删除。

## Acceptance boundary / 验收边界

| Check / 检查 | Result / 结果 |
| --- | --- |
| Package version / 包版本 | `4.14.0` |
| Trace schema / Trace schema | remains `0.1`; no Trace migration |
| Manifest safety / manifest 安全 | moving revisions and SHA-256 mismatches block |
| Decision/label separation / 决策与标签隔离 | `decide` never reads label meaning |
| Decision tampering / 决策篡改 | internal digest mismatch blocks scoring |
| Unsupported handling / unsupported 处理 | explicit count and IDs; never silently removed |
| Metrics / 指标 | confusion matrix plus Wilson 95% intervals |
| Core tests / 核心测试 | 235 tests pass locally |

The v4.13 τ² result remains calibration evidence because the same published
file informed the state-equivalence rules. It is intentionally not promoted to
a held-out generalization claim in v4.14. A genuinely held-out evaluation set,
with frozen Contracts committed before labels are read, remains a required
external-data gate for the later maturity release.

由于同一份公开文件参与了状态等价规则设计，v4.13 的 τ² 结果在 v4.14 仍被标记为 calibration
证据，不能升级为留出数据泛化成绩。真正的留出集、在读取标签前冻结 Contract，是后续成熟度
发布仍需补齐的外部数据门禁。
