# v4.28 acceptance / v4.28 验收

## Scope / 范围

v4.28 upgrades repeated-run stability evidence. A stability report now carries
Wilson 95% intervals for pass rate, structured-claims agreement and tool-error
rate, together with an explicit warning when fewer than 30 repeats were
observed. Projects can opt into a hard minimum with `--min-runs` or
`StabilityPolicy(min_runs=...)`.

v4.28 升级了重复运行稳定性证据：报告新增通过率、结构化 claims 一致率和工具错误率的
Wilson 95% 区间，并在实际重复次数少于 30 次时明确提醒。项目可以通过 `--min-runs` 或
`StabilityPolicy(min_runs=...)` 把最低重复数变成阻断门禁。

The default minimum remains `1`, so existing callers and old stability
configurations keep their behavior. The new interval fields are additive and
do not change Trace, Contract, Report or public API schema versions.

默认最低次数仍为 `1`，旧调用方和旧 stability 配置保持原有行为。区间字段是追加字段，不改变
Trace、Contract、Report 或公共 API 的 schema 版本。

## Design / 设计

| Field / 字段 | Meaning / 含义 |
| --- | --- |
| `uncertainty.pass_rate` | Wilson 95% interval over completed repeats that passed the Contract comparison |
| `uncertainty.claims_match_rate` | Wilson 95% interval over repeats whose structured claims match the baseline |
| `uncertainty.tool_error_rate` | Wilson 95% interval over recorded tool results with `is_error=true` |
| `sample_size.run_count` | Number of completed repeat records included in the report |
| `sample_size.recommended_minimum_runs` | Advisory threshold, currently 30 |
| `sample_size.small_sample_warning` | `true` when fewer than 30 repeats were observed |
| `policy.min_runs` | Optional hard minimum; the gate fails when completed repeats are fewer |

The interval is a description of finite observed evidence. It does not infer
unobserved model paths, read external benchmark labels, call an LLM judge or
claim a population reliability rate.

区间只描述已经执行的有限重复运行，不推断未观察到的模型路径，不读取外部 benchmark 标签，
不调用 LLM Judge，也不把结果表述成总体可靠率。

## Local acceptance / 本地验收

The core source suite passes 271 tests. The stability API and CLI were checked
with both the backward-compatible default and an explicit minimum:

核心源码测试通过 271 项。稳定性 API 和 CLI 同时验证了兼容默认值和显式最小次数：

```bash
PYTHONPATH=src python -m unittest tests.test_stability tests.test_statistics -q

PYTHONPATH=src python -m agent_regression.cli stability \
  --baseline baselines/order-123.trace.json \
  --scenario examples/order-123/candidate-ok.scenario.json \
  --repeats 30 \
  --workers 4 \
  --min-runs 30 \
  --format markdown \
  --out work/v428-sampling.md
```

The core CI performs the same 30-repeat sampling-boundary smoke and requires
`work/ci-reports/order-123.sampling.json` in the report index. A missing report
fails the index gate.

核心 CI 执行同样的 30 次重复采样边界 smoke，并要求
`work/ci-reports/order-123.sampling.json` 进入报告索引；报告缺失会让索引门禁失败。

## Acceptance cases / 验收用例

| Case / 用例 | Expected / 预期 |
| --- | --- |
| two completed identical repeats with default policy | comparison passes, interval and `small_sample_warning=true` are present |
| one repeat with `min_runs=2` | stability gate blocks without changing the comparison result |
| 30 completed repeats with `--min-runs 30` | gate passes and `small_sample_warning=false` |
| invalid count or confidence input | statistics helper raises a deterministic input error |

## Reproduce and inspect / 复现与查看

The JSON report is the machine-readable source. The Markdown renderer exposes
the same interval values and adds a human-readable small-sample warning. A
consumer can choose a stricter project policy without changing the framework's
default:

```python
from agent_regression import StabilityPolicy, record_stability

report = record_stability(
    baseline,
    scenario_case,
    repeats=30,
    policy=StabilityPolicy(min_runs=30, min_pass_rate=0.95),
)
assert report.passed
print(report.to_dict()["uncertainty"]["pass_rate"])
```

JSON 是机器读取的事实来源，Markdown 只是同一组区间的审阅呈现，并额外显示小样本警告。消费
项目可以设置更严格的策略，不需要改变框架的兼容默认值。

## Boundaries / 边界

- This is finite-sample uncertainty reporting over recorded repetitions, not
  online provider sampling-variance research.
- Thirty repeats are a project evidence threshold, not a universal statistical
  power calculation for every Agent workload.
- A stable Contract result does not prove that the Contract is complete or that
  hidden side effects and free-form factual claims are correct.
- No API key or external model provider is required by the v4.28 acceptance
  suite; a real provider can be supplied through the existing adapter boundary.

- 这是对已记录重复运行的有限样本不确定性报告，不是在线供应商采样方差研究。
- 30 次是项目证据门槛，不是适用于所有 Agent 工作负载的统一统计功效计算。
- Contract 结果稳定不代表 Contract 完整，也不代表隐藏副作用和自由文本事实正确。
- v4.28 验收不需要 API Key 或外部模型供应商；真实供应商仍可通过现有 Adapter 边界接入。
