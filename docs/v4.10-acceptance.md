# v4.10 acceptance / v4.10 验收

v4.10 adds scenario-level `contract.argument_rules`. It checks the arguments of
every candidate call for a named tool against deterministic literal values or
values already exposed in the candidate Trace. It closes the gap between
“this tool is allowed” and “this tool is being used within the tenant,
resource and business boundary of this scenario”.

v4.10 增加场景级 `contract.argument_rules`。它会对候选 Trace 中指定工具的每一次
调用执行确定性参数检查，用固定值或 Trace 中已经暴露的字段进行比较，补上“工具允许
调用”与“工具参数是否越过租户、资源和业务边界”之间的缺口。

## Scope / 范围

| Rule / 规则 | Meaning / 含义 |
| --- | --- |
| `tool` | Tool name selected by the rule. / 规则匹配的工具名。 |
| `path` | JSON path relative to that call's `arguments`. / 相对于该次调用 `arguments` 的 JSON 路径。 |
| literal operators | `equals`, `not_equals`, numeric comparisons and `in` use `value`. / 固定值运算符使用 `value`。 |
| path operators | `equals_path`, `not_equals_path`, numeric path comparisons use `right_path`. / 路径运算符使用 `right_path`。 |
| `exists` / `absent` | Require or forbid an argument path. / 要求参数存在或不存在。 |
| missing matching tool | Does not fail this rule; use `must_call` when presence is required. / 没有调用该工具时本规则不失败；要求出现请使用 `must_call`。 |

Rules are evaluated against every matching tool call. One invalid repeated
call is enough to create a blocking difference. The evaluator does not execute
user code or perform implicit string/number conversion.

规则会检查指定工具的每一次调用。重复调用中只要有一次违规，就会生成阻断差异。规则
执行器不执行用户脚本，也不会进行隐式字符串/数字类型转换。

## Configuration / 配置

```json
{
  "contract": {
    "tool_allowlist": ["get_order", "refund_order"],
    "argument_rules": [
      {
        "tool": "get_order",
        "path": "order_id",
        "operator": "equals_path",
        "right_path": "metadata.input.order_id",
        "message": "lookup must use the order from the request"
      },
      {
        "tool": "get_order",
        "path": "tenant_id",
        "operator": "equals_path",
        "right_path": "metadata.input.tenant_id",
        "message": "cross-tenant lookup is not allowed"
      },
      {
        "tool": "refund_order",
        "path": "amount",
        "operator": "less_or_equal_path",
        "right_path": "tool_results[0].result.paid_amount",
        "message": "refund amount must not exceed paid amount"
      },
      {
        "tool": "refund_order",
        "path": "admin_override",
        "operator": "absent",
        "message": "agent must not bypass the refund policy"
      }
    ]
  }
}
```

`metadata.input` is populated by `record_run` from the request. Other paths
must point to fields actually present in the candidate Trace. The rule is a
contract over observed evidence, not a replacement for authorization inside a
production Tool Gateway.

`metadata.input` 由 `record_run` 根据请求自动写入。其他路径必须指向候选 Trace 中
真实存在的字段。规则是对可观察证据的契约，不替代生产 Tool Gateway 中的权限控制。

## Failure evidence / 失败证据

```json
{
  "category": "tool_argument_policy",
  "path": "tool_calls[2].arguments.amount",
  "baseline": {
    "tool": "refund_order",
    "path": "amount",
    "operator": "less_or_equal_path",
    "right_path": "tool_results[0].result.paid_amount"
  },
  "candidate": {
    "value": [880],
    "right_values": [88]
  },
  "message": "refund amount must not exceed paid amount"
}
```

The path uses the zero-based index in the candidate tool-call list. The CLI
returns exit code `1`, so the violation can block a pull request.

路径使用候选工具调用列表中的从零开始索引。CLI 返回退出码 `1`，因此违规可以直接
阻断 Pull Request。

## Relationship to existing policies / 与已有策略的关系

- `tool_allowlist` answers which tools a scenario may touch.
- `argument_rules` answers whether each matching call uses safe arguments.
- `must_call` answers whether a required tool appeared at least once.
- `tool_limits` answers how many times a tool was called.
- `relations` remains the general-purpose rule for claims, results and state fields.

- `tool_allowlist` 约束场景可以触碰哪些工具；
- `argument_rules` 约束每一次匹配调用的参数是否安全；
- `must_call` 约束必须出现的工具；
- `tool_limits` 约束工具调用次数；
- `relations` 继续负责 claims、结果和状态字段之间的通用关系。

Do not duplicate the same fixed-index relation and argument rule unless the
report intentionally needs both diagnostics. Migrate a tool-argument rule from
`relations.left = tool_calls[index].arguments.*` to a tool-scoped rule when the
same condition should apply to every call of that tool.

如果同一条件应该适用于某个工具的每一次调用，不要同时重复配置固定下标的
`relations.left = tool_calls[index].arguments.*` 和 `argument_rules`；应将它迁移为按
工具匹配的规则，除非报告确实需要两种诊断。

## Acceptance cases / 验收场景

The repository covers:

仓库覆盖：

1. Literal equality, membership, numeric comparisons and nested argument paths.
2. Trace path comparisons against request input and tool results.
3. `exists` and `absent` behavior.
4. Missing reference evidence and incompatible types fail closed.
5. Every matching repeated tool call is checked.
6. A missing tool does not silently become a required-tool check.
7. Unknown fields and unsupported operators are rejected at configuration load time.
8. The refund business case detects wrong tenant, wrong order, excessive amount and forbidden override arguments.
9. Existing v4.9 allowlist, path, count and side-effect checks remain green.
10. The configuration viewer can import, edit and export argument rules.

1. 固定值相等、集合包含、数值比较和嵌套参数路径；
2. 与请求输入、工具结果进行 Trace 路径比较；
3. `exists` 与 `absent`；
4. 参考证据缺失和类型不兼容时 fail closed；
5. 检查同一工具的每一次重复调用；
6. 没有调用某工具时不会错误地替代 `must_call`；
7. 配置加载阶段拒绝未知字段和不支持的操作符；
8. 退款案例捕获错误租户、错误订单、超额金额和管理员绕过参数；
9. v4.9 的白名单、路径、次数和副作用测试继续通过；
10. 配置页面可以导入、编辑和导出参数策略。

## Compatibility / 兼容性

This is an additive optional Contract field. Configurations that omit
`argument_rules` retain their v4.9 behavior; Trace, baseline and report schemas
remain unchanged. The package rejects unknown contract fields instead of
silently ignoring typos.

这是可选的新增 Contract 字段。省略 `argument_rules` 的配置保持 v4.9 行为；Trace、
baseline 和 report schema 不变。框架会拒绝未知契约字段，不会静默忽略拼写错误。

The rules prove only what the Agent exposed in its Trace. A production system
must still enforce tenant isolation, resource authorization, amount limits and
idempotency at the real tool boundary.

规则只能证明 Agent 在 Trace 中暴露的行为。生产系统仍必须在真实工具边界执行租户
隔离、资源授权、金额限制和幂等控制。
